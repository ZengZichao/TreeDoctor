# IQ-TREE Output File Format Specification

This document details the format specifications for all output files generated by IQ-TREE (v2.4.0 / v3.1.4), serving as the development reference for TreeDoctor parsers. All format descriptions are based on actual IQ-TREE output files.

---

## 1. Main Report File: `prefix.iqtree`

### 1.1 Overview

The main report file is a plain-text format containing a complete summary of the IQ-TREE analysis. This is TreeDoctor's most critical parsing target.

### 1.2 File Structure (By Section)

The main report file consists of the following "sections," each starting with an all-caps title followed by a dashed separator line:

```
IQ-TREE 2.4.0 built Feb  7 2025

Input file name: ...
Type of analysis: ModelFinder + tree reconstruction + ultrafast bootstrap (1000 replicates)
Random seed number: 496837

REFERENCES
----------

SEQUENCE ALIGNMENT
------------------

ModelFinder
-----------

SUBSTITUTION PROCESS
--------------------

MAXIMUM LIKELIHOOD TREE
-----------------------

CONSENSUS TREE
--------------

ALISIM COMMAND
--------------

TIME STAMP
----------
```

### 1.3 Detailed Fields by Section

#### 1.3.1 Header

| Field | Format | Example | Parsing Notes |
|-------|--------|---------|---------------|
| IQ-TREE version | `IQ-TREE {major}.{minor}.{patch} built {date}` | `IQ-TREE 2.4.0 built Feb  7 2025` | Regex: `^IQ-TREE (\d+\.\d+\.\d+) built (.+)$` |
| Input file name | `Input file name: {path}` | `Input file name: example.phy` | |
| User tree file | `User tree file name: {path}` | (optional, only when user tree is specified) | |
| Analysis type | `Type of analysis: {description}` | `ModelFinder + tree reconstruction + ultrafast bootstrap (1000 replicates)` | Parse for ModelFinder, tree reconstruction, bootstrap |
| Random seed | `Random seed number: {number}` | `Random seed number: 496837` | |

#### 1.3.2 REFERENCES Section

This section lists references and contains no quantitative data to parse. TreeDoctor may skip it or use it for citation display.

#### 1.3.3 SEQUENCE ALIGNMENT Section

**Non-partitioned analysis format:**

```
Input data: 17 sequences with 1998 nucleotide sites
Number of constant sites: 686 (= 34.3343% of all sites)
Number of invariant (constant or ambiguous constant) sites: 686 (= 34.3343% of all sites)
Number of parsimony informative sites: 1009
Number of distinct site patterns: 1152
```

| Field | Regex Pattern | Data Type | Notes |
|-------|---------------|-----------|-------|
| Number of sequences | `Input data: (\d+) sequences` | int | |
| Number of sites | `with (\d+) ` | int | Total sites |
| Sequence type | `(\w+) sites$` | string | "nucleotide"/"amino-acid"/"codon"/"binary" |
| Constant sites | `Number of constant sites: (\d+) ` | int | |
| Constant site proportion | `\(= ([\d.]+)% of all sites\)` | float | Percentage |
| Invariant sites | `Number of invariant.*sites: (\d+)` | int | |
| Parsimony informative sites | `Number of parsimony informative sites: (\d+)` | int | |
| Distinct patterns | `Number of distinct site patterns: (\d+)` | int | |

**Partitioned analysis format:**

```
Input data: 10 taxa with 5 partitions and 5000 total sites (12.5% missing data)

  ID  Type  Seq  Site  Unique  Infor  Invar  Const  Name
   1  DNA   10   1000  800     500    200    150    gene1
   2  AA    10   1000  900     600    100    100    gene2
   ...
```

Partition table columns:

| Column | Meaning |
|--------|---------|
| ID | Partition number |
| Type | Sequence type (DNA/AA/CODON/BIN/MORPH/POMO) |
| Seq | Number of sequences |
| Site | Number of sites |
| Unique | Number of unique patterns |
| Infor | Number of informative sites |
| Invar | Number of invariant sites |
| Const | Number of constant sites |
| Name | Partition name |

#### 1.3.4 ModelFinder Section

```
Best-fit model according to BIC: TIM2+F+I+G4

List of models sorted by BIC scores: 

Model                  LogL         AIC      w-AIC        AICc     w-AICc         BIC      w-BIC
TIM2+F+I+G4      -21152.612   42383.224 +    0.069   42384.818 +   0.0791   42601.620 +    0.945
TIM2+F+G4        -21159.731   42395.462 - 0.000152   42396.975 - 0.000181   42608.259 -   0.0342
...
```

**Key parsing fields:**

| Field | Regex Pattern | Notes |
|-------|---------------|-------|
| Best model | `Best-fit model according to (\w+): (\S+)` | Criterion + model name |
| Model table rows | `^(\S+)\s+(-?[\d.]+)\s+([\d.]+)\s+([+-])\s+([\d.e-]+)\s+([\d.]+)\s+([+-])\s+([\d.e-]+)\s+([\d.]+)\s+([+-])\s+([\d.e-]+)` | Parse each row |

Model table columns:

| Column | Meaning |
|--------|---------|
| Model | Model name |
| LogL | Log-likelihood |
| AIC | AIC score |
| w-AIC | AIC weight (`+` = in 95% confidence set, `-` = significantly excluded) |
| AICc | Corrected AIC score |
| w-AICc | Corrected AIC weight |
| BIC | BIC score |
| w-BIC | BIC weight |

#### 1.3.5 SUBSTITUTION PROCESS Section

```
Model of substitution: TIM2+F+I+G4

Rate parameter R:

  A-C: 5.6922
  A-G: 7.7983
  A-T: 5.6922
  C-G: 1.0000
  C-T: 22.9838
  G-T: 1.0000

State frequencies: (empirical counts from alignment)

  pi(A) = 0.3547
  pi(C) = 0.2282
  pi(G) = 0.1919
  pi(T) = 0.2252

Rate matrix Q:

  A   -0.7511    0.2393    0.2757    0.2361
  C    0.3719    -1.361   0.03535    0.9533
  G    0.5095   0.04204    -0.593   0.04148
  T    0.3719    0.9663   0.03535    -1.374

Model of rate heterogeneity: Invar+Gamma with 4 categories
Proportion of invariable sites: 0.1687

 Category  Relative_rate  Proportion
  0         0              0.1687
  1         0.1059         0.2078
  2         0.4722         0.2078

```

**Key parsing fields:**

| Field | Regex Pattern | Notes |
|-------|---------------|-------|
| Substitution model | `Model of substitution: (\S+)` | |
| Rate parameters | `([A-Z]-[A-Z]): ([\d.]+)` | 6 substitution rates |
| State frequencies | `pi\(([A-Z])\) = ([\d.]+)` | 4 base/amino acid frequencies |
| Rate heterogeneity model | `Model of rate heterogeneity: (.+)` | |
| Invariable proportion | `Proportion of invariable sites: ([\d.]+)` | |
| Gamma shape | `Gamma shape alpha: ([\d.]+)` | |
| Rate categories | `^(\d+)\s+([\d.]+)\s+([\d.]+)$` | Category, relative rate, proportion |

#### 1.3.6 MAXIMUM LIKELIHOOD TREE Section

```
Log-likelihood of the tree: -21152.5219 (s.e. 336.2931)
Unconstrained log-likelihood (without tree): -11402.5956
Number of free parameters (#branches + #model parameters): 39
Akaike information criterion (AIC) score: 42383.0439
Corrected Akaike information criterion (AICc) score: 42384.6373
Bayesian information criterion (BIC) score: 42601.4400

Total tree length (sum of branch lengths): 4.2180
Sum of internal branch lengths: 0.9934 (23.5513% of tree length)

NOTE: Tree is UNROOTED although outgroup taxon 'LngfishAu' is drawn at root
Numbers in parentheses are SH-aLRT support (%) / ultrafast bootstrap support (%)

[ASCII tree diagram]

Tree in newick format:

(Newick string);
```

**Key parsing fields:**

| Field | Regex Pattern | Notes |
|-------|---------------|-------|
| Log-likelihood | `Log-likelihood of the tree: (-?[\d.]+)` | |
| Standard error | `\(s\.e\. ([\d.]+)\)` | Optional, may not exist |
| Unconstrained logL | `Unconstrained log-likelihood.*: (-?[\d.]+)` | |
| Free parameters | `Number of free parameters.*: (\d+)` | |
| AIC | `Akaike information criterion \(AIC\) score: ([\d.]+)` | |
| AICc | `Corrected Akaike.*\(AICc\) score: ([\d.]+)` | |
| BIC | `Bayesian information criterion \(BIC\) score: ([\d.]+)` | |
| Total tree length | `Total tree length.*: ([\d.]+)` | |
| Internal branch length | `Sum of internal branch lengths: ([\d.]+)` | |
| Internal branch ratio | `\(([\d.]+)% of tree length\)` | |
| Rooted status | `Tree is (ROOTED|UNROOTED)` | |
| Support value type | `Numbers in parentheses are (.+)` | May have multiple combinations |
| Newick tree | After `Tree in newick format:` | Separate line |

**Support value type parsing:**

The support annotation line `Numbers in parentheses are ...` can contain combinations separated by `/`:
- `SH-aLRT support (%)` — SH-aLRT test
- `local bootstrap support (%)` — local bootstrap
- `parametric aLRT support` — parametric aLRT
- `aBayes support` — aBayes test
- `standard bootstrap support (%)` — standard bootstrap
- `ultrafast bootstrap support (%)` — ultrafast bootstrap

Support values in Newick format are `SH-aLRT/UFBoot`, e.g., `100/100` or `85.5/71`.

#### 1.3.7 CONSENSUS TREE Section

```
Consensus tree is constructed from 1000 bootstrap trees
Log-likelihood of consensus tree: -21152.522112
Robinson-Foulds distance between ML tree and consensus tree: 0

Branches with support >0.000000% are kept (extended consensus)
Branch lengths are optimized by maximum likelihood on original alignment
Numbers in parentheses are bootstrap supports (%)

[ASCII tree diagram]

Consensus tree in newick format: 

(Newick string);
```

**Key parsing fields:**

| Field | Regex Pattern | Notes |
|-------|---------------|-------|
| Bootstrap replicates | `constructed from (\d+) bootstrap trees` | |
| Consensus logL | `Log-likelihood of consensus tree: (-?[\d.]+)` | |
| RF distance | `Robinson-Foulds distance.*: (\d+)` | RF distance between ML and consensus tree |
| Consensus threshold | `support >([\d.]+)%` | Branch retention threshold |
| Newick consensus tree | After `Consensus tree in newick format:` | |

#### 1.3.8 TIME STAMP Section

```
Date and time: Mon Oct 26 21:16:52 2026
Total CPU time used: 13.015625 seconds (0h:0m:13s)
Total wall-clock time used: 12.7092178 seconds (0h:0m:12s)
```

| Field | Regex Pattern | Notes |
|-------|---------------|-------|
| Completion time | `Date and time: (.+)` | |
| CPU time | `Total CPU time used: ([\d.]+) seconds` | |
| Wall-clock time | `Total wall-clock time used: ([\d.]+) seconds` | |

#### 1.3.9 Warning Messages

Warnings that may appear in the main report (TreeDoctor should identify and categorize):

| Warning Pattern | Meaning | Severity |
|----------------|---------|----------|
| `WARNING: ... near-zero internal branches (<...) should be treated with caution` | Near-zero internal branches | Medium |
| `WARNING: ... too long branches (>...) should be treated with caution!` | Overly long branches | Medium |
| `WARNING: This model has ... parameters that may be overfitting` | Model overfitting | High |
| `WARNING: K>=n, ... parameter estimates might be inaccurate` | Too many parameters | High |
| `**NOTE**: Consensus tree has higher likelihood than ML tree found!` | Consensus tree has higher likelihood | High |
| `NOTE: Tree is UNROOTED` | Tree is unrooted (informational, not a warning) | Info |
| `NOTE: The branch lengths of PoMo measure mutations and frequency shifts.` | PoMo model note | Info |

## 2. Log File: `prefix.log`

### 2.1 Overview

The log file records the complete IQ-TREE run, including detailed information not in the main report, especially the sequence composition test table.

### 2.2 Key Parsing Content

#### 2.2.1 Sequence Composition Chi-Square Test Table

```
           Gap/Ambiguity  Composition  p-value
Analyzing sequences: done in 5.93e-005 secs
   1  LngfishAu    0.15%    passed      6.20%
   2  LngfishSA    0.00%    failed      0.62%
   ...
****  TOTAL        0.11%  8 sequences failed composition chi2 test (p-value<5%; df=3)
```

**Per-line parsing:**

Each line format: `Index  SequenceName  Gap%  passed/failed  p-value%`

| Field | Format | Regex | Notes |
|-------|--------|-------|-------|
| Sequence index | Integer | `^\s*(\d+)` | May have leading spaces |
| Sequence name | String | `^\s*\d+\s+(\S+)` | |
| Gap/ambiguity ratio | Percentage | First `([\d.]+)%` | E.g., `0.15%`, `0.00%` |
| Composition test result | passed/failed | `(passed\|failed)` | |
| p-value | Percentage | Second `([\d.]+)%` | E.g., `6.20%`, `0.00%` |

**Note**: p-value is given as a percentage (e.g., `0.62%` means p=0.0062), not as a decimal.

**Total line parsing:**

```
****  TOTAL        0.11%  8 sequences failed composition chi2 test (p-value<5%; df=3)
```

| Field | Regex | Notes |
|-------|-------|-------|
| Total gap ratio | `TOTAL\s+([\d.]+)%` | |
| Failed sequence count | `(\d+) sequences failed` | |
| Significance threshold | `p-value<(\d+)%` | Note: `5%` not `0.05` |
| Degrees of freedom | `df=(\d+)` | Usually 3 for DNA data |

#### 2.2.2 Alignment Basic Information

```
Reading alignment file example.phy ... Phylip format detected
Alignment most likely contains DNA/RNA sequences
Alignment has 17 sequences with 1998 columns, 1152 distinct patterns
1009 parsimony-informative, 303 singleton sites, 686 constant sites
```

| Field | Regex | Notes |
|-------|-------|-------|
| File format | `(Phylip\|FASTA\|Nexus\|Clustal\|MSF) format detected` | |
| Sequence type | `most likely contains (DNA/RNA\|protein)` | |
| Sequence count | `Alignment has (\d+) sequences` | |
| Columns | `with (\d+) columns` | |
| Patterns | `(\d+) distinct patterns` | |
| Informative sites | `(\d+) parsimony-informative` | Note IQ-TREE's spelling |
| Singleton sites | `(\d+) singleton sites` | |
| Constant sites | `(\d+) constant sites` | |

#### 2.2.3 Bootstrap Convergence Metrics

```
NOTE: Bootstrap correlation coefficient of split occurrence frequencies: 1.000
```

| Field | Regex | Notes |
|-------|-------|-------|
| Bootstrap correlation | `Bootstrap correlation coefficient.*: ([\d.]+)` | Close to 1.0 = converged |

```
Log-likelihood cutoff on original alignment: -21183.131
```

| Field | Regex | Notes |
|-------|-------|-------|
| Likelihood cutoff | `Log-likelihood cutoff on original alignment: (-?[\d.]+)` | May appear multiple times; take last value |

#### 2.2.4 Iteration Information

```
Iteration 10 / LogL: -21152.627 / Time: 0h:0m:6s
...
Iteration 60 / LogL: -21153.134 / Time: 0h:0m:9s (0h:0m:3s left)
...
TREE SEARCH COMPLETED AFTER 102 ITERATIONS / Time: 0h:0m:11s
```

| Field | Regex | Notes |
|-------|-------|-------|
| Iteration number | `Iteration (\d+)` | |
| LogL | `LogL: (-?[\d.]+)` | |
| Elapsed time | `Time: (\S+)` | |
| Remaining time | `\((\S+) left\)` | Optional, some iterations include this |
| Total iterations | `COMPLETED AFTER (\d+) ITERATIONS` | |

#### 2.2.5 Likelihood Optimization Process

```
BETTER TREE FOUND at iteration 1: -21152.595
BEST SCORE FOUND : -21152.522
```

| Field | Regex | Notes |
|-------|-------|-------|
| Better tree likelihood | `BETTER TREE FOUND at iteration (\d+): (-?[\d.]+)` | |
| Best likelihood | `BEST SCORE FOUND : (-?[\d.]+)` | Final optimal likelihood |

#### 2.2.6 Model Selection Process

```
Akaike Information Criterion:           GTR+F+I+G4
Corrected Akaike Information Criterion: GTR+F+I+G4
Bayesian Information Criterion:         TIM2+F+I+G4
Best-fit model: TIM2+F+I+G4 chosen according to BIC
```

| Field | Regex | Notes |
|-------|-------|-------|
| AIC best model | `Akaike Information Criterion:\s+(\S+)` | |
| AICc best model | `Corrected Akaike Information Criterion:\s+(\S+)` | |
| BIC best model | `Bayesian Information Criterion:\s+(\S+)` | |
| Final best model | `Best-fit model: (\S+) chosen according to (\w+)` | Model name + criterion |

**Note**: The AIC/AICc best model may differ from the BIC best model. In this example, AIC/AICc selects `GTR+F+I+G4`, while BIC selects `TIM2+F+I+G4`.

## 3. ML Tree File: `prefix.treefile`

### 3.1 Format

Newick format, single line, terminated with semicolon. Support values embedded in branch name position as `SH-aLRT/UFBoot`.

### 3.2 Example

```
(LngfishAu:0.1710870825,(LngfishSA:0.1883807809,LngfishAf:0.1649399635)100/100:0.1072996568,...);
```

### 3.3 Parsing Notes

- Branch lengths are floating-point numbers after `:`
- Support values in `SH-aLRT/UFBoot` format at internal branch name position (no quotes)
- Support values are floating-point (e.g., `85.5/71`)
- Root node has no branch length
- Terminated with `;`

---

## 4. Consensus Tree File: `prefix.contree`

### 4.1 Format

Newick format, single line. Support values are pure bootstrap percentages (no SH-aLRT).

### 4.2 Example

```
(LngfishAu:0.1709947097,(LngfishSA:0.1883013207,LngfishAf:0.1648516204)100:0.1072583025,...);
```

### 4.3 Notes

- Consensus tree is only produced when bootstrap is enabled
- Support values are single numbers (bootstrap percentage), without `/`
- Branch lengths are re-optimized

---

## 5. Split Network File: `prefix.splits.nex`

### 5.1 Format

NEXUS format, containing Taxa block and Splits block.

### 5.2 Structure

```
#nexus

BEGIN Taxa;
DIMENSIONS ntax=17;
TAXLABELS
[1] 'LngfishAu'
[2] 'LngfishSA'
...
;
END; [Taxa]

BEGIN Splits;
DIMENSIONS ntax=17 nsplits=59;
FORMAT labels=no weights=yes confidences=no intervals=no;
MATRIX
	100	 2,
	100	 3,
	100	 2 3,
	...
	0	 7 8,
;
END; [Splits]
```

### 5.3 Key Fields

| Field | Description |
|-------|-------------|
| ntax | Number of taxa |
| nsplits | Total number of splits |
| Matrix rows | Format: `\tweight\t taxon1 taxon2 ...`, comma-terminated. First number is support (percentage), subsequent numbers are taxon indices |
| Support = 0 | Split did not appear in bootstrap |
| Support = 100 | Split appeared in all bootstrap trees |

### 5.4 Parsing Notes

- Number of splits with support > 0 can be used to assess tree topology reliability
- Low-support splits (< 50%) need special attention
- Can cross-validate with ML tree topology

## 6. ML Distance Matrix: `prefix.mldist`

### 6.1 Format

Phylip distance matrix format.

### 6.2 Structure

```
17
LngfishAu  0.0000000 0.4565546 0.4414905 ...
LngfishSA  0.4565546 0.0000000 0.3487336 ...
...
```

### 6.3 Parsing Notes

- First line is the number of sequences
- Subsequent lines: sequence name + pairwise distances (space-separated)
- Distances are ML-corrected distances
- Diagonal is 0.0
- Can be used to detect outlier sequences (too far or too close)

---

## 7. Model Details File: `prefix.model.gz`

### 7.1 Format

gzip-compressed plain text file containing complete parameters for all models tested by ModelFinder.

### 7.2 Parsing Notes

- Must decompress first
- Contains rate matrices, frequencies, likelihoods, etc. for each model
- Used for in-depth model comparison and analysis

---

## 8. Initial NJ Tree: `prefix.bionj`

### 8.1 Format

Newick format, with branch lengths but no support values.

### 8.2 Purpose

- Can be compared with ML tree for topological differences
- Used to assess search improvement

### 8.3 Notes

- BIONJ tree may contain negative branch lengths (e.g., `-0.0098774508`), which is normal
- BIONJ tree has no support values

---

## 9. Checkpoint File: `prefix.ckp.gz`

### 9.1 Format

gzip-compressed plain text file recording analysis state.

### 9.2 Content

- Contains current iteration state
- Candidate tree set
- Used for recovery after interruption

---

## 10. IQ-TREE 3.x Additional Features

### 10.1 Neural Network Models

IQ-TREE 3 introduces ONNX-based neural network models:
- `lanfear_alpha_lstm.onnx` — LSTM model for alpha prediction
- `resnet_modelfinder.onnx` — ResNet model for model selection

### 10.2 Output Format Differences

IQ-TREE 3.x main report structure is largely consistent with 2.x, but may include:
- Neural network-assisted model selection information
- Sequence type auto-detection note (`NOTE: Alignment sequence type is auto-detected`)
- Possible tree mixture model (MAST) information
- Concordance factor information

**Note**: IQ-TREE 3.x `.log` file header format is `IQ-TREE multicore version 3.1.4 ...`; version detection should be compatible with this format.

### 10.3 Version Detection

Detect IQ-TREE version via the first line of the `.iqtree` file:
- Regex: `^IQ-TREE (\d+)\.(\d+)\.(\d+)`
- Major version 2 → IQ-TREE 2.x
- Major version 3 → IQ-TREE 3.x
