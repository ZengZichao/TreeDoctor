# TreeDoctor 核心架构设计

本文档定义 TreeDoctor 的整体架构、模块划分、数据模型和接口规范。

---

## 1. 架构总览

TreeDoctor 采用**核心库 + 双前端**架构：

```
                        ┌─────────────────────────────────────┐
                        │          用户接口层                  │
                        ├──────────────┬──────────────────────┤
                        │   CLI 前端   │    GUI 前端 (Tauri)  │
                        │   (clap)     │    (React + WebView)  │
                        └──────┬──────┴──────────┬───────────┘
                               │                  │
                               │    Tauri IPC     │
                               │                  │
                        ┌──────▼──────────────────▼───────────┐
                        │         核心库 (Rust crate)          │
                        │          "treedoctor-core"          │
                        ├─────────────────────────────────────┤
                        │  文件发现 → 解析器 → 数据模型        │
                        │          → 交叉验证                  │
                        │          → 诊断引擎                  │
                        │          → 报告生成器                │
                        └─────────────────────────────────────┘
```

**设计原则**：
1. 核心逻辑全部在 Rust 核心库中实现，CLI 和 GUI 共享同一套解析和诊断引擎
2. 核心库是纯库（no I/O），文件读写由调用方传入路径
3. 诊断规则以插件化方式注册，便于扩展
4. 所有中间数据使用强类型数据模型，避免运行时错误

## 2. 核心库模块划分

### 2.1 模块树

```
treedoctor-core/
├── src/
│   ├── lib.rs                  # 库入口，公开 API

│   │   ├── registry.rs         # 规则注册表
│   │   ├── alignment_diag.rs   # D1: 对齐质量
│   │   ├── model_diag.rs       # D2: 模型选择
│   │   ├── likelihood_diag.rs  # D3: 似然与信息准则

│   │   ├── support_diag.rs    # D5: 分支支持值
│   │   ├── bootstrap_diag.rs   # D6: Bootstrap 收敛性
│   │   ├── consensus_diag.rs  # D7: 一致性树一致性
│   │   └── runtime_diag.rs    # D8: 运行参数
│   ├── crosscheck/             # 交叉验证
│   │   ├── mod.rs
│   │   └── rules.rs            # 7条交叉验证规则
│   └── report/                 # 报告生成
│       ├── mod.rs
│       ├── text.rs             # 纯文本报告格式
│       ├── json.rs             # JSON 结构化输出
│       └── markdown.rs         # Markdown 格式输出
```

### 2.2 模块依赖关系

```
parsers ──depends on──→ models
diagnostics ──depends on──→ models
crosscheck ──depends on──→ models
report ──depends on──→ models, diagnostics

lib.rs 公开 API:
  ├── analyze(input_dir) → Report
  ├── analyze_files(file_map) → Report
  ├── parse_file(path) → ParsedFile
```

## 5. 错误处理

### 5.1 错误类型

```rust
#[derive(Debug, thiserror::Error)]
pub enum TreeDoctorError {
    #[error("文件未找到: {path}")]
    FileNotFound { path: String },

    #[error("文件类型无法识别: {path}")]
    UnknownFileType { path: String },

    #[error("解析错误: {file_type} - {message}")]
    ParseError { file_type: String, message: String },

    #[error("缺少关键文件: {file_type}")]
    MissingCriticalFile { file_type: String },

    #[error("数据不一致: {message}")]
    DataInconsistency { message: String },

    #[error("IO 错误: {0}")]
    Io(#[from] std::io::Error),

    #[error("正则表达式错误: {0}")]
    Regex(#[from] regex::Error),

    #[error("JSON 序列化错误: {0}")]
    Json(#[from] serde_json::Error),
}
```

### 5.2 错误处理策略

| 错误类型 | 处理策略 |
|----------|----------|
| 关键文件缺失 | 降级运行：解析已有文件，在报告中标注缺失项 |
| 单文件解析失败 | 继续解析其他文件，在报告中标注失败项 |
| 数据不一致 | 记录为交叉验证警告，不中断分析 |
| 致命错误 | 返回错误，提供可操作的修复建议 |

## 6. 性能设计

### 6.1 目标

| 指标 | 目标值 |
|------|--------|
| 文件解析时间 | < 500ms（17 序列、2000 位点规模） |
| 诊断执行时间 | < 200ms |
| 报告生成时间 | < 100ms |
| 内存占用 | < 50 MB |
| CLI 总启动+运行时间 | < 1 秒 |

### 6.2 优化策略

1. **并行解析**：各文件类型的解析独立并行执行（使用 `rayon`）
2. **惰性解析**：仅在诊断规则需要时解析对应数据
3. **正则预编译**：所有正则表达式使用 `lazy_static` 或 `once_cell` 预编译
4. **零拷贝**：Newick 解析尽量使用字符串切片，避免不必要拷贝
5. **流式处理**：大文件（如 `.model.gz`）流式读取，不全量加载

## 7. 可扩展性设计

### 7.1 诊断规则插件化

```rust
/// 诊断规则 trait
pub trait DiagnosticRule: Send + Sync {
    /// 规则 ID
    fn id(&self) -> &str;
    /// 规则名称
    fn name(&self) -> &str;
    /// 所属维度
    fn dimension(&self) -> &str;
    /// 执行诊断
    fn evaluate(&self, data: &AnalysisData) -> DiagnosticResult;
    /// 所需的数据文件类型
    fn required_files(&self) -> Vec<FileType>;
}
```

新增诊断规则只需实现 `DiagnosticRule` trait 并注册到 `Registry` 中。

```rust
/// 文件解析器 trait

```

新增文件类型只需实现 `FileParser` trait 并注册。
