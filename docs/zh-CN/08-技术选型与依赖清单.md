# TreeDoctor 技术选型与依赖清单

本文档详细列出 TreeDoctor 的全部技术选型、第三方依赖、版本要求和选择理由。

---

## 1. Rust 核心库依赖

### 1.1 核心依赖

| crate | 版本要求 | 用途 | 选择理由 |
|-------|----------|------|----------|
| `regex` | ^1.10 | 正则表达式匹配 | IQ-TREE 输出解析的核心工具，性能好 |
| `serde` | ^1.0 | 序列化/反序列化框架 | 通用性强，与 JSON/YAML/TOML 兼容 |
| `serde_json` | ^1.0 | JSON 序列化 | CLI JSON 输出、Tauri IPC |
| `flate2` | ^1.0 | gzip 解压 | 解压 `.model.gz` 和 `.ckp.gz` |
| `rayon` | ^1.10 | 并行计算 | 多文件并行解析 |
| `thiserror` | ^1.0 | 错误类型定义 | 派生宏简化错误定义 |
| `anyhow` | ^1.0 | 通用错误处理 | 应用层错误传播 |
| `chrono` | ^0.4 | 日期时间处理 | 解析时间戳 |
| `once_cell` | ^1.19 | 惰性初始化 | 正则表达式预编译缓存 |
| `phf` | ^0.11 | 编译期哈希表 | 序列类型等静态映射 |

### 1.2 树解析依赖

| crate | 版本要求 | 用途 | 选择理由 |
|-------|----------|------|----------|
| `newick` | ^0.9 或自研 | Newick 树解析 | 基础 Newick 解析；若库不满足需求则自研 |

**Newick 解析器评估**：

| 方案 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 使用 `newick` crate | 成熟，无需重复造轮 | 可能不支持 IQ-TREE 的 `support/ufboot` 格式 | 先评估，不满足则自研 |
| 自研解析器 | 完全控制，支持 IQ-TREE 特殊格式 | 需要额外开发时间 | **推荐**：IQ-TREE Newick 有特殊的 `SH-aLRT/UFBoot` 格式，自研更灵活 |

### 1.3 日志与调试

| crate | 版本要求 | 用途 |
|-------|----------|------|
| `log` | ^0.4 | 日志门面 |
| `env_logger` | ^0.11 | 日志实现（开发期） |

### 1.4 测试依赖

| crate | 版本要求 | 用途 |
|-------|----------|------|
| `criterion` | ^0.5 | 基准测试 |
| `proptest` | ^1.4 | 属性测试 |

### CLI 模板

```rust
use clap::{Parser, Subcommand};

#[derive(Parser)]
#[command(name = "treedoctor")]
#[command(about = "IQ-TREE 分析质量诊断工具")]
#[command(version = "0.1.0")]
struct Cli {
    #[command(subcommand)]
    command: Option<Commands>,
}

#[derive(Subcommand)]
enum Commands {
    /// 分析 IQ-TREE 输出并生成诊断报告
    Analyze {
        #[arg(value_name = "INPUT")]
        input: PathBuf,
        
        #[arg(short, long)]
        prefix: Option<String>,
        
        #[arg(short, long, value_enum, default_value = "text")]
        format: OutputFormat,
        
        #[arg(short, long)]
        output: Option<PathBuf>,
        
        #[arg(short, long, value_delimiter = ',')]
        dimensions: Option<Vec<String>>,
        
        #[arg(short, long, value_enum)]
        min_grade: Option<Grade>,
        
        #[arg(short, long)]
        verbose: bool,
        
        #[arg(short, long)]
        quiet: bool,
        
        #[arg(long)]
        no_color: bool,
    },
    
    /// 快速检查文件完整性
    Check {
        #[arg(value_name = "INPUT")]
        input: PathBuf,
    },
    
    /// 列出所有诊断规则
    Rules {
        #[arg(long)]
        dimension: Option<String>,
    },
}
```

### 3.3 树可视化方案评估

| 方案 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 使用 `react-phylogeny-tree` | 可能有现成组件 | 搜索结果有限，可能不满足需求 | 调研 |
| 使用 `d3.js` 手工实现 | 完全可控 | 开发量大 | 备选 |
| 基于 `@antv/g6` | 图可视化能力强 | 需要适配树场景 | 备选 |
| **自研轻量树渲染器** | SVG/Canvas 渲染，完全可控 | 需要开发 | **推荐**：使用 SVG + React 组件，开发一个专用的系统发育树渲染组件 |

### 3.4 自研树可视化组件设计

```typescript
interface TreeViewProps {
  newick: string;
  layout: 'rectangular' | 'radial' | 'circular';
  showBranchLengths: boolean;
  showSupportValues: boolean;
  colorBySupport: boolean;
  highlightLowSupport: boolean;
  highlightAnomalies: boolean;
  onNodeClick?: (node: TreeNode) => void;
  onNodeHover?: (node: TreeNode) => void;
}

interface TreeNode {
  name: string | null;
  branchLength: number | null;
  support: number | null;
  secondarySupport: number | null;
  children: TreeNode[];
  // 计算属性
  x: number;
  y: number;
  depth: number;
  isLeaf: boolean;
}
```

渲染策略：
- 使用 SVG 绘制（支持矢量导出）
- React 组件管理状态和交互
- 分支用 `<path>` 元素绘制
- 节点用 `<circle>` 元素
- 标签用 `<text>` 元素
- 缩放和平移通过 SVG `viewBox` 实现

## 8. 版本控制策略

- 使用 Git，主分支 `main`
- 开发分支 `develop`
- 功能分支 `feature/*`
- 修复分支 `fix/*`
- 标签 `v0.1.0`
- 使用 Conventional Commits 规范

### Commit 消息格式

```
<type>(<scope>): <description>

类型: feat, fix, docs, style, refactor, test, chore
范围: parser, diagnostic, cli, gui, model, report
```

示例：
```
feat(parser): 添加 IQ-TREE 3.x 分区报告解析支持
fix(diagnostic): 修复 D5-R1 在无 UFBoot 时的崩溃
docs(gui): 更新树可视化组件设计文档
```
