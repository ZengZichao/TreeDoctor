# TreeDoctor 质量诊断规则体系

本文档定义 TreeDoctor 的全部质量诊断规则。每条规则包含：诊断维度、评估指标、数据来源、评级标准、解释文本和建议措施。所有规则按维度分组，构成一个多层次的系统发育分析质量评估体系。

---

## 1. 诊断维度总览

| 编号 | 维度 | 核心问题 | 规则数 |
|------|------|----------|--------|
| D1 | 对齐质量 | 序列数据本身是否有质量问题？ | 6 |
| D2 | 模型选择 | 替换模型选择是否合理？ | 5 |
| D3 | 似然与信息准则 | 似然值和信息准则是否正常？ | 4 |
| D4 | 树拓扑与分支长度 | 树的形态是否合理？ | 6 |
| D5 | 分支支持值 | 节点支持是否充分？ | 5 |
| D6 | Bootstrap 收敛性 | bootstrap 是否充分收敛？ | 4 |
| D7 | 一致性树与 ML 树一致性 | ML 树和一致性树是否一致？ | 3 |
| D8 | 运行参数与效率 | 运行配置是否合理？ | 3 |

**合计 36 条诊断规则。**

---

## 2. 评级标准

每个诊断维度和总体分析采用统一的评级体系：

| 等级 | 标签 | 颜色 | 含义 |
|------|------|------|------|
| A | 优秀 | 绿色 | 该方面质量很好，无问题 |
| B | 良好 | 浅绿 | 该方面质量较好，有轻微注意事项 |
| C | 一般 | 黄色 | 该方面存在中等程度问题，建议关注 |
| D | 警告 | 橙色 | 该方面存在明显问题，建议修正 |
| F | 严重 | 红色 | 该方面存在严重问题，分析结果可能不可靠 |

**总体评级规则**：取所有维度中最低的评级作为总体评级。若任何一个维度为 F，总体即为 F。

## 3. 维度 D1：对齐质量

### D1-R1：序列组成卡方检验

- **数据来源**：`.log` 文件中的组成检验表
- **评估指标**：未通过组成卡方检验（p < 0.05）的序列数及其占比
- **评级标准**：

| 条件 | 评级 | 说明 |
|------|------|------|
| 失败序列数 = 0 | A | 所有序列通过组成检验 |
| 失败序列占比 < 10% | B | 少量序列未通过，对整体影响有限 |
| 失败序列占比 10%-30% | C | 中等比例序列组成偏离，可能影响模型选择和建树 |
| 失败序列占比 30%-50% | D | 大量序列组成偏离，分析可靠性存疑 |
| 失败序列占比 > 50% | F | 组成检验大面积失败，数据可能不适用于似然法建树 |

**边界处理**：失败序列占比恰好等于 10% 时，取较高的评级（B）；恰好等于 30% 时取 C；恰好等于 50% 时取 D。

- **建议文本模板**：
  - A: "所有 {N} 条序列均通过了组成卡方检验（p ≥ 0.05），序列核苷酸组成均衡。"
  - B/C: "{n} 条序列（{pct}%）未通过组成卡方检验（p < 0.05），列表：{seq_names}。建议检查这些序列是否存在测序错误、污染或长程同塑性。可考虑使用复合模型（如 PoMo）或排除问题序列。"
  - D/F: "超过 {pct}% 的序列未通过组成检验。序列组成系统性偏离将导致模型选择偏差和分支长度估计不准确。强烈建议：1）检查数据质量；2）考虑使用组成异质性模型（如 Lie Markov 模型）；3）排除组成偏差最大的序列。"

### D1-R2：Gap/歧义字符比例

- **数据来源**：`.log` 文件中的 Gap/Ambiguity 列
- **评估指标**：每条序列的 gap 比例和总体 gap 比例
- **评级标准**：

| 条件 | 评级 | 说明 |
|------|------|------|
| 所有序列 gap 比例 < 5% | A | gap 极少 |
| 存在序列 gap 比例 5%-20% | B | 少量 gap |
| 存在序列 gap 比例 20%-50% | C | 中等 gap 比例 |
| 存在序列 gap 比例 > 50% | D | 单条序列 gap 过多 |
| 总体 gap 比例 > 20% | F | 全局 gap 过多，数据质量差 |

- **建议文本**：
  - B/C: "序列 {seq_names} 含有较高比例的 gap/歧义字符（> {pct}%）。大量 gap 可能影响比对质量和建树准确性。建议检查比对对齐情况。"
  - D/F: "序列 {seq_name} 的 gap 比例高达 {pct}%，建议排除该序列。总体 gap 比例 {total_pct}% 过高，考虑重新比对或使用 gap-aware 方法。"

### D1-R3：序列数量充分性

- **数据来源**：`.iqtree` 文件 SEQUENCE ALIGNMENT 节
- **评估指标**：序列数（分类群数）
- **评级标准**：

| 条件 | 评级 | 说明 |
|------|------|------|
| 序列数 ≥ 50 | A | 序列数充足 |
| 序列数 20-49 | B | 序列数基本充足 |
| 序列数 10-19 | C | 序列数偏少 |
| 序列数 4-9 | D | 序列数过少 |
| 序列数 < 4 | F | 无法进行可靠的系统发育分析 |

- **建议文本**：
  - C: "当前数据集包含 {N} 条序列。建议至少使用 20 条以上序列以获得更可靠的拓扑估计。"
  - D: "仅 {N} 条序列，系统发育推断的统计功效不足，节点支持值可能偏高。建议增加分类群采样。"

### D1-R4：信息位点充分性

- **数据来源**：`.iqtree` 文件 SEQUENCE ALIGNMENT 节
- **评估指标**：信息位点数和比例
- **评级标准**：

| 条件 | 评级 | 说明 |
|------|------|------|
| 信息位点比例 > 30% 且信息位点数 > 500 | A | 信息含量丰富 |
| 信息位点比例 15%-30% 或信息位点数 100-500 | B | 信息含量尚可 |
| 信息位点比例 5%-15% 或信息位点数 50-100 | C | 信息含量偏低 |
| 信息位点比例 < 5% 或信息位点数 < 50 | D | 信息含量不足 |
| 信息位点数 < 10 | F | 数据几乎没有系统发育信号 |

- **建议文本**：
  - C: "信息位点占比 {pct}%（{n} 个），系统发育信号偏弱。建议增加序列长度或补充更多变异位点。"
  - D/F: "信息位点极少（{n} 个，{pct}%），数据缺乏足够的系统发育信号。建议：1）增加比对长度；2）检查比对是否正确；3）考虑使用更快速的演化区域。"

### D1-R5：恒定位点比例

- **数据来源**：`.iqtree` 文件 SEQUENCE ALIGNMENT 节
- **评估指标**：恒定位点比例
- **评级标准**：

| 条件 | 评级 | 说明 |
|------|------|------|
| 恒定位点比例 < 50% | A | 变异位点充分 |
| 恒定位点比例 50%-70% | B | 变异位点尚可 |
| 恒定位点比例 70%-85% | C | 恒定位点偏多 |
| 恒定位点比例 > 85% | D | 数据高度保守 |
| 恒定位点比例 > 95% | F | 数据几乎无变异 |

### D1-R6：序列长度充分性

- **数据来源**：`.iqtree` 文件 SEQUENCE ALIGNMENT 节
- **评估指标**：比对长度（位点数）
- **评级标准**：

| 条件 | 评级 | 说明 |
|------|------|------|
| 长度 ≥ 1000 | A | 序列长度充足 |
| 长度 500-999 | B | 序列长度基本充足 |
| 长度 200-499 | C | 序列长度偏短 |
| 长度 50-199 | D | 序列长度过短 |
| 长度 < 50 | F | 序列长度严重不足 |

## 4. 维度 D2：模型选择

### D2-R1：最优模型是否经过 ModelFinder 自动选择

- **数据来源**：`.iqtree` 文件 Type of analysis 行和 ModelFinder 节
- **评估指标**：是否使用了 ModelFinder（`-m MFP` 或 `TEST`）
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 使用了 ModelFinder | A |
| 手动指定了模型但模型合理 | B |
| 使用了默认/不恰当的模型（如 JC） | D |

- **建议文本**：
  - D: "当前分析手动指定了 {model} 模型，未使用 ModelFinder 自动选择。建议使用 `-m MFP` 让 IQ-TREE 自动选择最优模型，避免模型误设导致的分析偏差。"

### D2-R2：最优模型的复杂性是否合理

- **数据来源**：`.iqtree` 文件 ModelFinder 节和 ML TREE 节
- **评估指标**：模型自由参数数（df）与样本量（位点数）的比例
- **评级标准**：

| 条件 | 评级 | 说明 |
|------|------|------|
| n > 40K | A | 样本量远大于参数数 |
| 40K ≥ n > K | B | 样本量大于参数数 |
| n ≤ K | F | 参数数等于或超过样本量，过拟合 |

（其中 n = 样本量/位点数，K = 自由参数数）

**注意**：这里的 n 应使用不同模式数（`n_patterns`）而非原始位点数，因为似然计算基于模式压缩后的数据。但在实际操作中，IQ-TREE 的警告 `K>=n` 使用的是模式数。文档中统一使用 n 表示模式数。

- **建议文本**：
  - F: "自由参数数 K={K} 已达到或超过样本量 n={n}（K≥n）。模型严重过拟合，参数估计不可靠。IQ-TREE 也已发出警告。建议：1）使用更简单的模型；2）增加序列长度；3）减少序列数。"

### D2-R3：不同信息准则下的最优模型一致性

- **数据来源**：`.iqtree` 文件 ModelFinder 节
- **评估指标**：AIC、AICc、BIC 三个准则选出的最优模型是否一致
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 三个准则选择同一模型 | A |
| AIC 和 AICc 一致但 BIC 不同 | B |
| AIC/AICc 与 BIC 选择不同模型 | C |

- **建议文本**：
  - C: "AIC/AICc 推荐模型为 {aic_model}，而 BIC 推荐 {bic_model}。BIC 对参数数量惩罚更重。若数据量充足，建议使用 AICc 推荐；若数据量有限，建议使用 BIC 推荐以避免过拟合。"

### D2-R4：速率异质性模型评估

- **数据来源**：`.iqtree` 文件 SUBSTITUTION PROCESS 节
- **评估指标**：Gamma shape alpha 值
- **评级标准**：

| 条件 | 评级 | 说明 |
|------|------|------|
| alpha > 0.5 | A | 速率异质性适中 |
| alpha 0.1-0.5 | B | 速率异质性较高 |
| alpha < 0.1 | D | 速率异质性极高，少数位点主导似然 |
| 未使用 +G | C | 未建模速率异质性 |

- **建议文本**：
  - D: "Gamma shape alpha = {alpha}，非常低。这意味着速率异质性极高，少数位点以极高速率变化。这可能表明数据中存在饱和位点或高变区。建议检查数据质量或考虑去除高变区。"

### D2-R5：不变位点比例评估

- **数据来源**：`.iqtree` 文件 SUBSTITUTION PROCESS 节
- **评估指标**：Proportion of invariable sites (pinv)
- **评级标准**：

| 条件 | 评级 |
|------|------|
| pinv 与恒定位点比例大致一致 | A |
| pinv 明显低于恒定位点比例 | B |
| pinv 接近 0 且 alpha 低 | C |
| pinv 接近 1 | F |

## 5. 维度 D3：似然与信息准则

### D3-R1：对数似然值合理性

- **数据来源**：`.iqtree` 文件 MAXIMUM LIKELIHOOD TREE 节
- **评估指标**：最终 ML 对数似然值
- **说明**：似然值本身无绝对评判标准，但可与无约束似然值比较
- **评级标准**：需结合 D3-R2

### D3-R2：似然比（约束 vs 无约束）

- **数据来源**：`.iqtree` 文件
- **评估指标**：`tree_lh - unconstrained_lh` 的差值
- **评估说明**：差值越负（绝对值越大），说明树模型对数据的拟合越好
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 差值 < -100 | A |
| 差值 -100 ~ -10 | B |
| 差值 -10 ~ -1 | C |
| 差值 > -1 | D |

### D3-R3：似然值标准误

- **数据来源**：`.iqtree` 文件 `Log-likelihood of the tree: X (s.e. Y)`
- **评估指标**：标准误与似然值绝对值的比例
- **评级标准**：

| 条件 | 评级 |
|------|------|
| s.e. / |lnL| < 1% | A |
| s.e. / |lnL| 1%-5% | B |
| s.e. / |lnL| > 5% | D |

### D3-R4：信息准则值变化趋势

- **数据来源**：`.iqtree` 文件 ModelFinder 节
- **评估指标**：最优模型与次优模型的 BIC/AICc 差值及权重比
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 最优模型权重 > 0.9 | A |
| 最优模型权重 0.5-0.9 | B |
| 最优模型权重 0.1-0.5 | C |
| 最优模型权重 < 0.1 | D |

## 6. 维度 D4：树拓扑与分支长度

### D4-R1：近零内部分支

- **数据来源**：`.iqtree` 文件 ML TREE 节的 WARNING 行
- **评估指标**：近零内部分支数量
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 近零内部分支数 = 0 | A |
| 近零内部分支数 1-2 | C |
| 近零内部分支数 > 2 | D |

- **建议文本**：
  - C/D: "检测到 {n} 个近零长度的内部分支（<{threshold}）。这些分支对应的节点关系不确定，可能代表快速辐射进化或多分叉。建议：1）增加数据量；2）尝试不同模型；3）对这些节点使用多分叉表示。"

### D4-R2：过长分支

- **数据来源**：`.iqtree` 文件 ML TREE 节的 WARNING 行
- **评估指标**：过长分支数量
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 过长分支数 = 0 | A |
| 过长分支数 1-2 | C |
| 过长分支数 > 2 | D |

- **建议文本**：
  - C/D: "检测到 {n} 个异常长的分支（>{threshold}）。过长分支可能表明：1）长枝吸引（Long Branch Attraction）；2）序列差异过大；3）数据质量问题。建议检查对应序列并与参考序列比对。"

### D4-R3：总树长合理性

- **数据来源**：`.iqtree` 文件
- **评估指标**：总树长（所有分支长度之和）
- **说明**：DNA 数据的合理树长通常在 0.1-10 之间
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 0.1 ≤ 树长 ≤ 10 | A |
| 树长 < 0.1 或 > 10 | C |

### D4-R4：内部分支占比

- **数据来源**：`.iqtree` 文件
- **评估指标**：内部分支总长占树长的百分比
- **评估说明**：内部分支占比高通常表示拓扑信号强
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 内部分支占比 > 30% | A |
| 内部分支占比 15%-30% | B |
| 内部分支占比 5%-15% | C |
| 内部分支占比 < 5% | D |

### D4-R5：负分支长度检测

- **数据来源**：`prefix.treefile` Newick 解析
- **评估指标**：是否存在负分支长度
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 无负分支长度 | A |
| 存在负分支长度 | F |

### D4-R6：异常序列距离检测

- **数据来源**：`prefix.mldist` 距离矩阵
- **评估指标**：每条序列到其他序列的平均距离的离群程度
- **评估方法**：计算每条序列的平均距离，使用 IQR（四分位距）法检测离群值
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 无离群序列 | A |
| 存在 1 条离群序列 | C |
| 存在 > 1 条离群序列 | D |

## 7. 维度 D5：分支支持值

### D5-R1：低支持值节点数

- **数据来源**：`prefix.treefile` Newick 解析（支持值）
- **评估指标**：SH-aLRT < 80% 或 UFBoot < 95% 的内部分支数
- **评级标准**（以 UFBoot 为主要指标）：

| 条件 | 评级 | 说明 |
|------|------|------|
| 所有内部分支 UFBoot ≥ 95% | A | 所有序列支持值充分 |
| 低支持分支数 ≤ 总内部分支数的 10% | B | 少量低支持节点 |
| 低支持分支数 10%-30% | C | 中等比例低支持节点 |
| 低支持分支数 30%-50% | D | 大量低支持节点 |
| 低支持分支数 > 50% | F | 多数节点支持不足 |

**注意**：若未使用 UFBoot（仅使用标准 bootstrap 或 SH-aLRT），则评级标准中的 UFBoot 阈值替换为对应的支持值类型阈值（标准 bootstrap ≥ 70%，SH-aLRT ≥ 80%）。

- **建议文本**：
  - C/D/F: "共有 {n} 个内部分支的 UFBoot 支持值 < 95%（占 {pct}%）。这些节点的拓扑关系不可靠。建议：1）增加 bootstrap 重复次数；2）增加序列数据；3）对这些节点使用保守的解读。低支持分支：{branch_list}"

### D5-R2：完全无支持节点

- **数据来源**：`prefix.treefile`
- **评估指标**：UFBoot < 50% 的分支数
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 无 | A |
| 存在 1-2 个 | C |
| 存在 > 2 个 | F |

### D5-R3：SH-aLRT 与 UFBoot 一致性

- **数据来源**：`prefix.treefile` 中的 `SH-aLRT/UFBoot` 格式
- **评估指标**：SH-aLRT 和 UFBoot 的差异模式
- **评估说明**：SH-aLRT ≥ 80% 但 UFBoot < 95% 可能表示支持不足；SH-aLRT < 80% 但 UFBoot ≥ 95% 可能表示过高支持
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 两者一致（都高或都低） | A |
| 存在分歧节点 | C |

### D5-R4：支持值分布

- **数据来源**：`prefix.splits.nex`
- **评估指标**：支持值分布的偏度
- **评估方法**：统计支持值在各区间（0-25%, 25-50%, 50-75%, 75-100%）的分布
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 多数分裂支持值 > 75% | A |
| 支持值分布均匀 | B |
| 多数分裂支持值 < 50% | D |

### D5-R5：是否使用了足够的 bootstrap 重复次数

- **数据来源**：`.iqtree` 文件 Type of analysis 行
- **评估指标**：UFBoot 重复次数
- **评级标准**：

| 条件 | 评级 |
|------|------|
| UFBoot ≥ 1000 | A |
| UFBoot 500-999 | B |
| UFBoot 100-499 | C |
| UFBoot < 100 | D |
| 未使用 bootstrap | F（仅当用户期望有支持值时） |

## 8. 维度 D6：Bootstrap 收敛性

### D6-R1：Bootstrap 相关系数

- **数据来源**：`.log` 文件
- **评估指标**：Bootstrap correlation coefficient
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 相关系数 ≥ 0.99 | A |
| 相关系数 0.95-0.99 | B |
| 相关系数 0.90-0.95 | C |
| 相关系数 < 0.90 | D |

- **建议文本**：
  - D: "Bootstrap 相关系数为 {corr}，低于 0.90，表明 bootstrap 可能未充分收敛。建议增加 `-bb` 重复次数或使用 `-bnni` 选项进行额外的 NNI 优化。"

### D6-R2：似然截止值变化

- **数据来源**：`.log` 文件中多次出现的 `Log-likelihood cutoff on original alignment` 行
- **评估指标**：多次记录的似然截止值之间的变化幅度
- **评估说明**：UFBoot 过程中会多次输出似然截止值，取第一次和最后一次的值计算变化率。变化率 = |最后值 - 首次值| / |首次值| × 100%
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 截止值变化 < 1% | A |
| 截止值变化 1%-5% | B |
| 截止值变化 > 5% | C |

### D6-R3：迭代次数充分性

- **数据来源**：`.log` 文件
- **评估指标**：实际迭代次数 vs 默认最小迭代次数（通常 100）
- **评级标准**：

| 条件 | 评级 |
|------|------|
| 迭代次数 ≥ 100 | A |
| 迭代次数 50-99 | C |
| 迭代次数 < 50 | D |

### D6-R4：一致性树似然与 ML 树似然比较

- **数据来源**：`.iqtree` 文件
- **评估指标**：一致性树似然 vs ML 树似然
- **评级标准**：

| 条件 | 评级 |
|------|------|
| ML 树似然 > 一致性树似然 | A |
| 一致性树似然 > ML 树似然（差值 < 0.1） | B |
| 一致性树似然 > ML 树似然（差值 ≥ 0.1） | F |

- **建议文本**：
  - F: "一致性树的对数似然（{con_lh}）高于 ML 树（{ml_lh}），差值 {diff}。这表明 ML 搜索可能未找到全局最优树，IQ-TREE 已发出 NOTE 警告。建议使用一致性树替代 ML 树，或重新运行分析增加搜索强度。"

## 12. 交叉验证规则

除诊断规则外，TreeDoctor 还执行以下跨文件一致性检查：

| 编号 | 检查项 | 涉及文件 | 说明 |
|------|--------|----------|------|
| X1 | 序列数一致性 | `.iqtree` vs `.log` vs `.mldist` | 三个文件中的序列数应一致 |
| X2 | 模型名称一致性 | `.iqtree` ModelFinder 节 vs SUBSTITUTION PROCESS 节 | 最优模型应一致 |
| X3 | 似然值一致性 | `.iqtree` ML TREE 节 vs `.log` BEST SCORE | 最终似然值应一致 |
| X4 | 树拓扑一致性 | `.treefile` Newick vs `.iqtree` 内嵌 Newick | 两处树字符串应一致 |
| X5 | 支持值一致性 | `.treefile` 支持值 vs `.splits.nex` 分裂支持 | ML 树中的支持值应与 splits 文件对应 |
| X6 | bootstrap 次数一致性 | `.iqtree` Type of analysis vs CONSENSUS TREE 节 | bootstrap 重复次数应一致 |
| X7 | 一致性树 Newick 一致性 | `.contree` vs `.iqtree` 内嵌一致性树 Newick | 两处应一致 |

每条交叉验证规则失败时产生一条 **数据一致性警告**（不参与评级，但单独标注）。
